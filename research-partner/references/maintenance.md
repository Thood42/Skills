# Maintenance — Phases 6 and 7

Bootstrap only covers session one. **The vault carries its own work queue**, in the schema, visible to both the agent and the human, so that a resumed session has something concrete to pull from instead of restating scope or re-deriving what's missing. Phase 6 is growth; Phase 7 is upkeep. Most resumed sessions do some of each.

---

## Phase 6 — the growth loop

### Where the work comes from

Three queues, in priority order:

1. **Open questions** — `bases/questions.base#Open`, sorted by `priority`. These were seeded in Phase 3 from the scope's own open threads and added to on every pass. This is the primary queue.
2. **`gaps-report.md`** — regenerated by `kg gaps`. Low-degree entities (linked but never explained), unsourced notes, low-confidence claims, questions open more than 30 days, and Adamic–Adar suggested links.
3. **The Inbox** — `bases/inbox.base`, every `status: seed` note. Ingested and agent-seeded material awaiting a human decision.

### The loop

```bash
python3 -m scripts.kg gaps                    # refresh the report
# read bases/questions.base#Open and gaps-report.md; pick ONE thing
```

Then: brief a single subagent using the template in `subagent-dispatch.md`, scoped to that question. Give it the question note's filename so it can set `answers:` on what it writes.

On return:

```bash
python3 -m scripts.kg build
python3 -m scripts.kg generate
python3 -m scripts.kg doctor                  # must PASS
```

Then close the loop by hand:
- Update the question note: `status: open` → `researching` → `answered`, with `answered-by` pointing at what closed it. A question note that stays `open` after being answered poisons the queue for every future session.
- Re-run `kg communities --write` **only if** membership moved materially, and rewrite the analyst prose for any cluster whose members changed.
- Append to `project-log.md`: what you asked, what you found, what you closed.

### One thing at a time

The temptation on a resumed session is to run five subagents and close five questions. Resist it. The consolidation and doctor gate cost the same either way, but a five-way pass makes it much harder to tell which subagent produced the notes that failed — and the review of the merge report gets correspondingly worse.

## Phase 7 — maintenance

### The review queue

`bases/review.base` — notes where `status: stale`, or `review-after <= today`. Every note gets a `review-after` 90 days out when written. Working through this queue is the thing that keeps a research vault from becoming a snapshot of what was true the week it was built.

For each: re-check the claim against current sources, then either bump `review-after` and `updated`, raise or lower `confidence`, or mark it `stale` with a note about what changed.

### Inbox triage

Everything at `status: seed` is a **candidate, not evidence**. That includes claims from `kg ingest` and claims a subagent wrote but could not fully source. Promote deliberately:

- confirmed against the source → `status: verified`, `confidence` raised, `asserted-by` adjusted if a human confirmed it
- wrong or unsupported → delete the note, or demote to `status: disputed` with a `contradicts` edge to what refutes it

An Inbox that only grows is a sign the vault is accumulating rather than learning.

### Contradiction triage

```bash
python3 -m scripts.kg contradictions
```

Returns two very different things, and conflating them is an overclaim:

- **Explicit** — pairs joined by a real `contradicts` edge that somebody asserted. These are findings. Surface them in `bases/claims.base#Disputed` and work them: which is better sourced, is there a `qualifies` edge that dissolves the conflict, does one need `valid-from` / `valid-to` because both were true at different times?
- **Latent tension candidates** — high embedding similarity plus a shared `about` target and no declared relationship. This is a *similarity heuristic*. The schema has no stance comparison behind it, so it has not detected disagreement; it has detected two notes that talk about the same thing in similar language. Some will be genuine tensions, some will be near-duplicates that should be merged, most will be neither. Present them as candidates for a human eye, never as detected contradictions.

Requires embeddings; without them the latent scan is skipped and says so.

### Community summaries

Regenerate when membership shifts materially — roughly 20% of a cluster's members changing.

```bash
python3 -m scripts.kg communities --write --min-size 3
```

The command writes the notes and the member lists. **You write the analyst prose**, 150–250 words per cluster, inside the `<!-- ANALYST SUMMARY -->` markers, from actually reading the member list. Those markers are what preserve your text across regeneration.

A stale summary describing a cluster that has moved on is worse than none, because `kg context` lifts it into every retrieval pack for that cluster. Clusters below `--min-size` correctly get a database row and no note.

### Suggested links

Adamic–Adar candidates in `gaps-report.md`: pairs of notes with enough shared neighbours that they probably should be connected directly. **Never auto-applied.** Read each, and when one is right, add the edge to the note's frontmatter with the predicate that actually describes the relationship — not a generic `about`.

A useful calibration: if fewer than about 70% of the suggestions look reasonable to the user, the graph is too sparse for link prediction to be meaningful yet, and the effort belongs in Phase 6 instead.

### Ingestion

```bash
python3 -m scripts.kg ingest <path.pdf|url>
```

Extracts, chunks, and writes a `source` note plus candidate `claim` notes at `status: seed`, into the Inbox. Nothing arrives verified. Page-level provenance is preserved where the extractor can get it.

## The weekly digest (optional)

Offered at Phase 5. A scheduled task that runs `kg gaps` and `kg contradictions`, writes `digests/YYYY-WW.md`, and pushes a one-paragraph summary.

Use the platform's scheduled-task mechanism, not an in-process cron — an in-session scheduler dies with the session and the user's digest silently never runs.

Worth it for an ongoing project; noise for a weekend deep-dive. Ask which one this is.

---

## Invariants that must hold after every maintenance pass

```bash
bash scripts/rebuild.sh          # build → generate → doctor, doctor ends PASS
```

- `kg doctor` PASS. A non-PASS doctor is a broken vault, not a warning. When it goes PASS → FAIL after a change, that is a regression to fix now, not to note and move on (see `hardening-ledger.md` R4).
- Two consecutive no-op `communities --write` + `build` cycles produce byte-identical output.
- `python3 scripts/init_project.py verify .` PASSes, if you touched the predicate vocabulary.
- Nothing under `.kg/` was hand-edited. If you were tempted to, the fix belongs in a note or in the compiler.
